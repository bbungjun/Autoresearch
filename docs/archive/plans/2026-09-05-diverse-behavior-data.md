# #107 행동 다양성 데이터 생성 계획

## 목적과 범위

#105의 최근 count 상수를 해소할 데이터 생성·품질 검사 작업이다. 기존 fixture v1/v2와
production 피처 계약은 유지한다. 모델 학습·ranking 비교·final 소비는 후속 실험이다.

## 생성 전에 고정한 설계

- 새 `diverse-behavior-v1` 생성기는 seed 10701/10702/10703, 사용자 200명(기존
  bucket 선택의 validation 160/final 40)을 사용한다. 이 사용자 분류는 향후 사용을
  위한 ID 선택일 뿐 이번 작업에서 final 평가를 하지 않는다.
- KST 2026-08-03~09-01은 30일 선행 이력, 09-02는 학습 대상, 09-03은 클릭
  귀속 확인일이다. 32개 파티션을 오름차순 생성한다. 평가일 09-04와 이후는 생성하지 않는다.
- 사용자 고정 활동 수준과 사용자·날짜별 결정적 난수로 접속 여부, 8/16/24개 노출,
  클릭 여부를 만든다. 카테고리 선호와 독립적인 영상별 noise로 클릭 후보를 정한다.
- 일부 사용자는 시작 후 14~21일에 선호 카테고리를 전환한다. 이 잠재 상태는
  생성기 감사 전용이며 사용자 metadata에 미래 선호를 공개하지 않는다.
- `ImpressionDraft` 이후 production event 확장/Parquet writer를 재사용해 event ID,
  slate, impression→click→view→like 시간 계약을 지킨다. 접속하지 않은 날도 빈/비어
  있지 않은 일별 파일로 coverage를 표현한다. 기존 최대 1 click/slate와 click→view 결합은 유지한다.
- raw 사용자/영상 schema는 기존 버전을 재사용하되 metadata 관측 시각은 KST 하루
  시작으로 설정한다. 생성 알고리즘·seed·날짜·writer/source hash와 파일 receipt를 기록한다.

## 검증 및 종료 조건

1. 날짜·seed·출력경로 검증과 같은 seed 재현성, 다른 seed 차이, 순서 독립 난수 회귀.
2. 날짜 경계·전역 ID 고유성·클릭의 선행 노출·slate 멤버 수를 실제 생성 로그에서 검사.
3. 실제 local_features로 학습일 이전 7/30일을 조립한다. 전체 사용자와 실제 학습
   노출 모두 최근 5개 각각 unique>=2, std>0이고 null이 없어야 한다. 당일·이후 행을
   제거해도 최근 피처가 같고 coverage가 완전해야 한다. 감사용 상수 임베딩은 ranking에 사용하지 않는다.
4. 관심 전환은 설정값만이 아니라 전환 전/후 클릭 카테고리 비율로 확인한다.
   전환 사용자 중 양쪽 클릭이 있는 사례 수와 새 선호 카테고리 비율 변화, stable 대조를 기록한다.
5. 3개 seed 데이터와 checksum/감사 결과를 보존하고 독립 리뷰·CI·포트폴리오 문서를 완료한다.

## 한계

합성 규칙의 다양성은 실제 사용자 대표성이나 최근 피처의 ranking 기여를 증명하지 않는다.
활동 수준은 latent 고정값이고 click/view는 구조적으로 연동된다. 관심 전환 관측이 부족하면
그 실패를 기록하며, 평가 결과를 보고 seed를 골라내거나 기존 final을 재사용하지 않는다.
