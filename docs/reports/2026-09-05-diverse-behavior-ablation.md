## #115 — 저장 validation 예측의 정답 순위 이동 분석

### 문제와 분석 방법

#113의 validation에서 Recall@10은 0.839655→0.825394로 감소했지만 NDCG@10은 0.466742→0.471595로 증가했다. 평균 지표만으로는 어떤 순위 이동이 서로 다른 방향의 변화를 만들었는지 알 수 없었다. 새로운 실험 대신 저장된 validation 예측을 정답 순위로 분해했다.

분석 범위는 3개 cohort의 validation 19,600행, 1,232개 추천 목록(slate)이다. 이 중 클릭이 있는 689개 목록은 모두 정답이 1개이며, 사용자마다 목록 1개다. 무클릭 543개 목록은 기존 ranking 지표와 동일하게 제외한다. 동일 689개 목록을 3개 학습 seed에서 비교한 **2,067개 목록·seed 쌍**을 분석하며, 이를 독립 사용자 2,067명으로 해석하지 않는다.

기존 `ranking_metrics.py`의 score 내림차순·video_id 오름차순 정렬을 그대로 적용했다. `(evaluation_id, slate_id, video_id)` 키의 고유성·양쪽 행 집합·유한 점수와 validation label/slate의 manifest 해시, 예측 CSV의 봉인 해시를 대조했다. 정답과 같은 점수를 가진 다른 후보는 없었다. 단일 정답의 순위가 r이면 Recall@10은 `1[r≤10]`, NDCG@10은 `1[r≤10]/log2(r+1)`이다.

각 쌍의 기여 가중치는 `1/(9×해당 cohort의 클릭 양성 목록 수)`다. 따라서 cohort별 표본 수 252/218/219가 달라도 원래의 9개 실험 단순평균과 일치한다. 2,067건을 한꺼번에 나눈 값과 공식 평균은 다를 수 있다. 저장된 18개 validation 지표의 Recall/NDCG를 각각 절대 오차 1e-12 이내로 재현했고, 분해 기여의 합도 원래 Δ와 일치했다.

### Recall 감소와 NDCG 상승의 기여 분해

아래 건수는 목록·seed 쌍이며, 기여는 전체 validation 평균 변화에 대한 가산 성분이다.

| 정답 순위 변화(10피처→15피처) | 건수 | NDCG@10 기여 | Recall@10 기여 |
| --- | ---: | ---: | ---: |
| 10위 안에서 순위 개선 | 625 | +0.070768 | 0 |
| 10위 안에서 순위 악화 | 567 | −0.060828 | 0 |
| 10위 밖→안으로 진입 | 107 | +0.019623 | +0.051692 |
| 10위 안→밖으로 이탈 | 137 | −0.024710 | −0.065954 |
| 10위 안에서 동일 순위 | 406 | 0 | 0 |
| 두 모델 모두 10위 밖 | 225 | 0 | 0 |
| 합계 | 2,067 | **+0.004853** | **−0.014261** |

**Recall은 이탈 137건이 진입 107건보다 30건 많아서 감소했다.** NDCG는 10위 내부 순서 변경의 순기여 +0.009939778이 진입·이탈의 순손실 −0.005086975를 상쇄해 +0.004852803이 됐다. 단순히 일부 사례가 그런 것이 아니라, 전체 평균 변화가 이 분해로 설명된다.

정답 1위 건수는 361→383, 3위 이내는 875→913으로 늘었지만, 10위 이내는 1,735→1,705로 줄었다. 이탈 사례의 평균 정답 순위는 약 6.53→14.05위였고, 이탈 137건 중 49건은 원래 5위 이내였다. 따라서 손실 전체를 10위·11위 경계의 작은 순서 변경으로 설명할 수 없다.

### 피처 원인으로 해석할 수 있는 범위

저장된 validation 입력 전체에서 최근 행동 5개 열은 같은 목록 안의 모든 후보에게 동일한 값이었다. 이 열들은 사용자 활동량을 나타내며 특정 영상에 대한 선호를 직접 구분하는 값은 아니다. 다만 트리에서는 사용자 활동에 따라 다른 영상 피처와 결합한 분기로 갈 수 있으므로, 목록 내 상수라는 이유만으로 순위에 영향을 주지 않는다고 결론내리면 안 된다.

실제 학습 경로는 `behavior_execution.py`에서 `LGBMModel`을 호출하며, `lgbm_model.py`는 `LGBMClassifier(objective="binary")`를 사용한다. 이 모델은 클릭 여부를 학습하고, 추천 목록의 상위 10개 포함 여부를 직접 최적화하는 학습 목적은 사용하지 않는다. 이 차이는 후속 실험 가설의 근거지만 **이번 Recall 감소의 인과 원인으로 확인한 것은 아니다**. 특정 최근 행동 열, click/view 중복, 활동량과 목록 크기 중 무엇이 손실을 유발했는지는 별도 통제 실험이 필요하다.

### 검증·재현과 다음 판단

분석 산출물은 `rank-transitions.csv`(쌍별 순위·기여), `transition-counts.csv`(순위 이동 집계), `metric-reconciliation.csv`(18개 지표 대조), `analysis.json`, `input-hashes.json`이다. 입력 58개 파일은 분석 전후 해시가 같았다. 이는 준비 summary 1개, snapshot manifest 3개, validation label/slate 6개, 예측 봉인 목록 3개, feature receipt 3개, feature/key 6개, 예측 18개, 저장 metrics 18개다. 공식 Judge 호출·학습·새 예측·final 예측/정답 파일 열람·final 소비는 없었다.

독립 검토는 원본 validation 예측을 별도의 Python 기본 정렬로 재구성해 2,067개 쌍의 순위·분류·가중 기여를 모두 대조했고, 기존 지표 및 입력 해시가 일치했다. `analysis.json`의 SHA256은 `4400270172c158dbbcda5d883b571f4533823592538ed7b3fd780f1fba4a6f02`, 순위 CSV의 SHA256은 `cecaceb8085c86ff33bac236b7c24a7e2d3db6dea5f195d5fa2c222cd06c0d45`다. 분석 스크립트와 행별 산출물은 로컬에 보존하고 사용자·영상 ID와 로컬 전용 경로는 커밋하지 않는다.

이번 작업은 **지표 변화의 순위상 원인 확인**을 완료했다. #113의 `not_supported` 판정은 유지한다. 다음 후보는 24개 목록의 손실을 주요 진단 항목으로 삼아, 기존 binary 학습과 목록 단위 순위 학습을 동일 조건에서 비교하는 사전 등록 실험이다. 이번 validation 분석 결과를 본 이후의 가설이므로, 효과 확증에는 별도의 신규 평가 데이터가 필요하다. 이미 소비한 final을 다시 사용하지 않는다.
