# 고정 모델의 보정 표본 확대 실험 (#119)

개발과 신규 final에서 사전 등록 기준을 통과하여 **supported**로 종료했다.
선호 피처 모델의 추천 순위를 그대로 유지하면서 보정 표본 확대가 확률 오차를 줄였다.
이는 합성 평가에서의 후보 채택 근거이며 production 배포·실사용자 성능 보증은 아니다.

## 문제와 연구 질문

#117은 선호 피처의 ranking 개선에도 final Brier가 0.000100439 악화하여 기각됐다.
당시 보정 표본의 클릭 정답은 모델별 9~14개였다. 작은 보정 표본이 확률 추정에
영향을 주는지 확인하려고 **모델과 보정법을 고정하고 표본만 확대**했다.
Brier는 보정과 판별력을 함께 반영하므로 이전 악화의 원인을 이것만으로 단정하지 않는다.

[사전 등록](../archive/specs/2026-09-06-calibration-sample-experiment.md)은
결과 관측 전에 커밋 `a38b82c`로 고정했다. 실제 완료 실행은 `e96247f` 기준이다.
기본/선호 모델 12개와 기존 보정을 그대로 사용하며, 기존 calibration20%와
reserve20%를 합쳐 같은 양의 기울기 sigmoid를 12회 fit했다. 모델 fit은 0회다.
보정법·피처·모델 변경을 함께 적용하면 원인을 분리할 수 없어 범위에서 제외했다.

모델 fit 사용자와 보정 사용자는 서로소이고, 기본/선호 모델의 확대 표본 membership은
같다. reserve는 이전 다른 larger arm에서 쓰였으나 이번 고정 모델들의 fit에는 쓰이지 않았다.
원래 개발 예측 12개를 재사용하고 지표를 재현했다. 총 개발24·final24관측이며,
신규 cohort11901/11902/11903은 각 validation200/final800명이다. 신규 validation은 채점하지 않았다.
8/3 anchor → 9/4 평가 → 9/5 귀속 tail의 합성 날짜 계약을 유지했다.
3world×2seed의 6쌍은 독립 사용자 실험6개를 뜻하지 않는다.

## 고정 판정과 결과

보정 효과는 preference_expanded 대 preference의 Brier 평균 개선>0,
개선≥4/6쌍·≥2/3world, LogLoss 평균 무악화를 요구한다.
채택은 추가로 preference_expanded 대 원래 baseline15의 Recall 평균Δ≥0.005,
양수≥4/6쌍·≥2/3world, 나머지 ranking/AUC 및 Brier/LogLoss 평균 무악화를 요구한다.
두 단계 모두 개발과 final에서 통과해야 supported다. 기본 모델의 확대 보정은 진단용이다.

표준 Brier와 LogLoss는 작을수록 좋다.

해석하지 않는다. 이전 final은 재사용·재판정하지 않았다. 이번 새 cohort에서
동일 모델의 보정 확대가 추가 개선을 보였다는 것이 관측된 결론이다.

## Brier가 줄어든 부분과 남은 오차

각 행의 `(예측확률−정답)^2`를 클릭/비클릭으로 나누어 전체 행 수로 나눈
가산 기여를 구했다. 아래 값은 6관측의 동일 가중 평균으로, 두 기여의 합이 Brier다.

| final 선호 모델 | 비클릭 기여 | 클릭 기여 | 합계 |
|---|---:|---:|---:|
| 기존 보정 | 0.004958871 | 0.028103390 | 0.033062261 |
| 확대 보정 | 0.004081379 | 0.028562113 | 0.032643492 |

비클릭 오차 기여는 0.000877492 줄었지만 클릭 기여는 0.000458723 늘었다.
클릭 정답에 대한 조건부 평균 오차도 0.810622→0.823811로 악화했다.
**전체 개선은 비클릭 오차 감소가 클릭 오차 증가보다 컸기 때문**이다.
개발에서도 같은 방향이었다. 모든 확률이 더 정확해졌다는 주장은 하지 않는다.

확률 구간별 final 진단은 아래와 같다. 두 seed가 같은 행을 예측하므로 아래의 수는
고유 사용자가 아닌 예측 건수이며, 구간 membership도 보정 전후 달라진다.
구간을 넘나든 동일 개체 효과나 새로운 채택 검정으로 해석하지 않는다.

표본 확대만으로 보정 문제가 완전히 해소된 것은 아니다.

## 검증·실행 비용·보존

관련 회귀 109 passed, 전체 Ruff·diff check 통과. 독립 코드 리뷰에서 과거 cohort
manifest pin/평가ID 제외 목록 누락을 발견해 수정했으며 새 테스트20개를 독립 확인했다.
실행 실패를 숨기지 않고 다음과 같이 구분했다.

1. 첫 CLI 기동: supervisor의 keyword-only timeout을 위치 인자로 전달하여 TypeError.
   worker 생성 전이므로 fit/final/output0. 호출을 고치고 실제 시그니처 autospec 회귀 추가.
2. 첫 worker prepare: `recall_code_hash_mismatch`, fit0/final0, 0.720초.
   Windows CRLF checkout과 Git 원본 LF의 바이트 차이였다. 원래 Git blob 해시가 기존
   receipt와 정확히 일치하여 파일만 원바이트로 복원했다. pin·receipt·검증 조건은 변경하지 않았다.
   독립 리뷰에서도 원인과 원본 모델12개 artifact pin을 대조했다.
3. 실패 출력은 보존하고 다른 폴더에서 최초 fit12회를 완료했다. 학습 실패 재시도·
   추가fit·final 재소비는 없었다. 첫 worker의 공통 claim 미생성도 확인했다.

모델 재사용 시 원본 코드 SHA256은
`f379e5d37c8b46bcc67a8e328c05c4301b91cb882d1a1f99e014ceaf5cc30179`여야 한다.
Windows의 줄바꿈 자동 변환은 같은 커밋에서도 byte pin을 깨뜨릴 수 있으므로
기존 원본 바이트 대조가 선행돼야 한다. 이것은 이번 복구의 운영 한계다.

완료 실행은 총 **173.810초**, 모델 fit0·보정 fit12·final claim3·유료 API0이다.
E5는 기존 모델 identity/cache를 사용해 27 cache hit, miss0, inference0이었다.
따라서 이번 실행에서 새 GPU 임베딩 추론을 수행했다고 주장하지 않는다.
OS sandbox는 비활성인 로컬 신뢰코드 실행이다.

독립 결과 감사는 판정함수를 재사용하지 않고 저장24 final관측을 재집계하여
supported와 일치함을 확인했다. 48예측 hash·저장지표·Brier 진단 합계, 6개의 8예측 봉인,

CI·머지 상태는 연결 PR에 기록한다. Windows 전체 회귀는 이전 #117에서
관측한 범위 밖 OS 관련 실패 때문에 반복하지 않았으며 전체 로컬 통과를 주장하지 않는다.

## 후속 연구

후보는 합성 평가 기준으로 채택 가능하지만 배포는 수행하지 않았다.
다음은 p≥0.2 구간의 과대 추정과 클릭 오차 악화를 줄이는 보정법/규제의 통제 비교가
가능하다. 이번 final은 소비 완료했으므로 후속 연구는 개발 데이터에서 후보·기준·예산을
사전 등록하고 별도 신규 final로 검증해야 한다. 추가 실험은 이번 범위에서 실행하지 않았다.
실사용자 데이터, 다른 날짜/행동 정책, 온라인 A/B 일반화는 아직 입증되지 않았다.
